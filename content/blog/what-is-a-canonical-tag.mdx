A canonical tag is a small piece of HTML that tells search engines which URL is the main, preferred version of a page when the same or very similar content is available at more than one address. It uses the rel=canonical attribute and goes in the head section of the page. You can create one instantly with the free [RankBoost Canonical Tag Generator](/tools/canonical-generator).

## What a canonical tag looks like

A canonical tag is a single line of HTML:

```html
<link rel="canonical" href="https://example.com/blog/seo-guide" />
```

The href value is the canonical URL — the address you want search engines to treat as the original. Every page that shares the same content can point to that one URL.

## Why canonical tags matter

Duplicate and near-duplicate URLs are surprisingly common, and they're often created without anyone noticing. A single product page might be reachable at:

- `https://example.com/shoes/trail-runner`
- `https://example.com/shoes/trail-runner?color=blue`
- `https://example.com/sale/trail-runner`
- `http://example.com/shoes/trail-runner`

To a person, these are the same page. To a search engine, they can look like separate URLs with identical content. That can lead to several problems:

- **Split signals.** Links and other signals may be spread across several versions instead of consolidated on one.
- **The wrong URL in results.** A search engine might show a parameter-filled URL instead of your clean one.
- **Wasted crawling.** Crawlers spend time on duplicate URLs instead of your new or updated pages.

A canonical tag helps solve these issues by indicating which version you prefer. It's worth knowing that Google treats the canonical tag as a strong hint, not a strict command. If other signals conflict, it may choose a different canonical.

## When to use a canonical tag

Common situations where canonical tags help include:

- **URL parameters** for tracking, sorting or filtering.
- **The same product in multiple categories**, creating several paths to one page.
- **HTTP and HTTPS or www and non-www versions** that both resolve (redirects are usually the better fix, with canonicals as backup).
- **Syndicated content**, where your article is republished on another site that agrees to point a canonical back to you.
- **Printer-friendly or AMP-style versions** of a page.

## Self-referencing canonicals

A page can, and usually should, point its canonical to itself. This is called a self-referencing canonical. It makes your preference explicit, so if someone links to your page with tracking parameters attached, search engines still get a clear signal about the clean URL.

## Canonical tag best practices

### Use absolute URLs

Always include the full address, with protocol and domain. Relative URLs are more prone to errors, especially across staging and live environments.

### Use only one canonical per page

Multiple canonical tags with different URLs send mixed signals, and search engines may ignore them all. Check that your theme, plugins and templates aren't each adding their own.

### Point to an indexable page

The canonical URL should return a normal, successful response, be crawlable and not carry a noindex tag. Pointing to a redirected, blocked or broken URL undermines the signal.

### Keep signals consistent

Your internal links, XML sitemap and canonical tags should all point to the same preferred URL. Listing non-canonical URLs in a sitemap creates conflicting hints. The same goes for structured data: if you add JSON-LD with the [Schema Markup Generator](/tools/schema-generator), use the canonical URL in its url field.

## Common canonical mistakes

- **Canonicalising every page to the homepage.** This tells search engines all your pages are duplicates of one, which can stop them from being indexed properly.
- **Pointing paginated pages to page one** when they contain different content.
- **Mixing canonical and noindex** on the same page, which sends contradictory instructions.
- **Using canonicals instead of redirects** when an old URL should simply no longer exist.
- **Blocking the canonical URL in robots.txt**, which prevents crawlers from confirming it. Our [Robots.txt Generator](/tools/robots-txt-generator) can help you review your crawl rules.

## Canonical tag vs 301 redirect

| | Canonical tag | 301 redirect |
| --- | --- | --- |
| Visitors | Can still view every version | Sent automatically to the new URL |
| Search engines | Receive a strong hint | Receive a clear signal the page has moved |
| Best for | Duplicates that need to stay accessible | Pages that have permanently moved |

## FAQ

### Do canonical tags work across different domains?

Yes. Cross-domain canonicals are commonly used for syndicated content, where a partner site republishes your article and points the canonical back to your original URL.

### Is a canonical tag the same as noindex?

No. Noindex asks search engines not to include a page in results. A canonical tag says another URL is the preferred version and helps consolidate signals there.

### Can I add a canonical tag in an HTTP header?

Yes, for non-HTML files such as PDFs, a canonical can be sent as a Link HTTP header. For regular web pages, the HTML link element is the most common approach.

### How do I know if Google respects my canonical?

URL inspection in Google Search Console shows both the canonical you declared and the one Google selected. If they differ, check for conflicting signals like internal links or sitemap entries.
